3. 四层架构与目录映射

沿用参考项目验证过的单向依赖分层（附录 04），目录按本项目命名：

① Monitoring 监控层 · StatusButlerCore/Monitoring/
每信号一个监控器，全部协议化（any BatteryMonitoring…），可注入假实现测试。含：BatteryMonitor(IOKit) / WiFiMonitor(CoreWLAN) / ConnectionMonitor(NWPath) / VPNProbe / VolumeMonitor(CoreAudio) / InputMonitor / BluetoothDeviceController(IOBluetooth+配件电源) / NearbyBLEScanner(CoreBluetooth) / MobileBatteryHelperReader(iDevice) / E11 新增 ThermalController(AppleSMC 读温度与转速) + FanControlEngine(纯函数曲线引擎) + 特权 Helper(SMAppService，仅风扇键白名单，见 A5) / E1 新增 SlotSource 系列（Clock/NetRate/CPU/Memory/GPU…设计见 A7）
▲ 只产出状态值
② Store 状态仓库层 · Store/StatusStore.swift + Models/
@MainActor ObservableObject，聚合为单一 StatusSnapshot（Equatable：快照相等 = 图标不变）；弹层专用旁路状态（VPN/受限网络/可见性）独立 @Published 不进快照。子控制器：电池详情 / Wi-Fi 网络 / 主链路 / 蓝牙 / 移动电池 / 聆听模式 / 槽位调度器（E1）。
▲ 纯映射，无系统调用
③ Presentation 展示映射层 · Presentation/（Icon + Panel）
图标侧：IconSceneMapper → IconSceneState（外环/中心/底部三段；底部段在 E1 下由槽位协议供给）；面板侧：PanelMapper → 分区 ViewModel。纯函数，测试直接覆盖。
▲ 只消费场景状态
④ UI 层 · UI/ + App/
StatusBarController（菜单栏壳）/ PopoverView（SwiftUI 内容）/ Settings/（S9 设置中心）/ Icon/（渲染器+缓存）；App/ 放生命周期（激活策略、Dock 点击、登录项、单实例、Sparkle、充电效果时钟、动作中心 E2）。

横向模块：Audio/（CoreAudio+DDC 封装）、Localization/、Telemetry/（OG-FR-201，默认关）。组合根 AppEnvironment.live() 手工装配全部依赖——main 极薄，AppDelegate 只管生命周期。

4. 数据流与能效策略

系统事件推送＋ 兜底轮询 15s→ Monitors→ StatusStore→ @Published snapshot→ IconSceneMapper→ 渲染器 ×2

能效纪律（具名常量 + 注释故事，照抄参考项目的推导）：

  • 电池每 tick 刷新（画在图标上不能陈旧）；Wi-Fi/音量仅界面不可见时每第 4 tick刷（推送丢失看门狗）；
  • 显示器睡眠跳过轮询，但最多连跳 20 次（防唤醒通知丢失冻结读数的自愈上限）；
  • 定时器宽容 = 间隔 1/5（不要求 CPU 精确唤醒）；弹层打开 500ms 防抖合并；
  • E1 槽位采样器按需启停：仅选中该槽或弹层可见时 1s 采样，其余时间零开销；
  • 设置订阅一律 removeDuplicates()，防回写回环。

6. 工程纪律（AGENTS 规则）

项目根建 AGENTS.md（AI 协作与人工变更共同遵守），首批条款直接继承参考项目的有效实践（附录 05），替换为本项目参数：

  1. CI 即验收：本地过 ≠ 能合并；提交前 swift test + swift build -c release；触碰 actor 隔离/SwiftUI 绑定/资源加载的改动，额外跑一次不发布的 release workflow 预检。
  2. SDK ≥ 26：构建脚本与 verify-platform-version.sh 双保险，旧 SDK 直接失败（防静默旧外观）。
  3. 两端对等：图标渲染或图标设置的任何改动，菜单栏与 Dock 同一变更内完成（设置派生→订阅→缓存 key→渲染→测试五处同步）。
  4. 事故入档：每次 CI 失败登记 docs/ci-compatibility.md（run、根因、修复、验证）；真实事故转化为永不删除的回归测试。
  5. 设置面板路由：深跳必须落到目标面板自己的 Settings 扩展；验证看加载的扩展而非 open 退出码；路由测试钉死顺序。
  6. 红线四条（A2·S12）写进 AGENTS 与守卫扫描（check-forbidden-patterns）：禁密码/钥匙串、禁越权写入、私有 API 白名单仅 DDC。
  7. 发布纪律：版本/构建号显式递增；Release 正文 zh-Hans + en；appcast 每语言独立节点、en 第一；Developer ID 版不附 quarantine 指引。
  8. 设计文档快照制：规格不追溯修改，行为变更新开日期文档并在旧文档顶部声明"以××为准"。

7. 测试与发布链

  • 测试体系：监控器协议化注入假实现（单元层）；映射层纯函数直测；图标几何/像素指纹回归（首个动画功能起引入）；本地化 parity（en vs zh-Hans）；守卫测试扫红线模式。目标：测试代码 ≥ 业务代码（参考项目 1.4:1）。
  • 发布流水线：GitHub Actions（release.yml，tag/手动触发）＝ swift test + release build → SDK 断言 → .app 组装（+Helper 若启用）→ 签名/公证（有 Secrets 时 Developer ID，否则 Ad-hoc 回退）→ DMG + SHA-256 → Release（zh-Hans+en 正文）→ appcast 生成与校验。契约脚本：SDK 版本、Sparkle 元数据、最低系统版本、Helper RPATH/依赖。
  • 测试框架决策：本项目测试采用 Swift Testing（import Testing，已实测在 swiftly 工具链下无需 Xcode 完整运行），不照搬参考项目的 XCTest（XCTest 只随完整 Xcode 提供）。测试风格对齐参考项目的分层思路：协议注入假实现的单元层 + 纯函数映射直测 + 图标几何/像素指纹回归 + 本地化 parity + 红线守卫扫描。
  • 本机就绪度：编译链已实测通过（swiftly Swift 6.4，25.5s 全量构建）；测试链已实测通过（Swift Testing 无 Xcode 运行）；gh 已装待登录——见附录 07 状态表。
