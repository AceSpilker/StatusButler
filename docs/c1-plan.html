一、开发规范（写码前必读）

1.1 仓库与分支

  • 分支模型：main 常绿 + 短生命周期功能分支（feat/xxx、fix/xxx、docs/xxx）；小改动直进 main，大改动（跨子系统/触碰图标渲染）走分支并跑全量测试。
  • 提交信息：Conventional Commits + 中文描述（feat: 温度监控读取路径 (T-025)）；每个提交在末行标注任务号，保证可追溯。
  • 推送节奏：每完成一个任务即 commit+push；CI（GitHub Actions）跑构建与测试。

1.2 Swift 编码规范

  • Swift 6 严格并发：状态仓库与控制器 @MainActor；nonisolated(unsafe) 仅限 teardown 场景并注释论证；不把 actor 隔离方法直接当函数值传。
  • 命名：类型大驼峰、方法动词开头；监控器协议以 -ing 结尾（BatteryMonitoring）；设置键与 UserDefaults 键一一对应并集中声明。
  • 能效铁律：采样器"有人看才运行"；定时器带宽容忍；订阅一律 removeDuplicates()。
  • 注释只写"为什么"（约束/边界/坑），不写"是什么"。

1.3 架构铁律（违反 = 打回）

  1. 四层依赖单向：Monitoring → Store → Presentation → UI，禁止反向 import；
  2. 菜单栏与 Dock 图标改动必须同一提交内两端同步（设置/订阅/缓存/渲染/测试五处）；
  3. 能画进图标的进 StatusSnapshot，只服务面板的走旁路属性；
  4. 四条产品红线（A2·S12）+ 守卫扫描测试钉死；
  5. 改功能先改规格文档（A2/A5~A12），再写代码——文档是唯一事实源。

1.4 测试规范（完成的定义）

  • 框架：Swift Testing（import Testing，免 Xcode）；监控器全部注入假实现测试；映射层纯函数直测。
  • 一个任务"已完成"必须同时满足：① 代码合并 ② 单测通过并登记测试报告（第四节）③ 契约脚本通过（涉及图标/发布时）④ 文档同步。
  • 提交前检查：swift build && swift test 全绿（CI 重复执行）。
