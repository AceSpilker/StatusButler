A6 / Desktop Widgets（E12 深度设计）

桌面小组件：把状态放到桌面上

状态管家的第 12 号扩展（E12）：用 WidgetKit 提供桌面小组件——温度、风扇、三合一状态、性能等模块信息常驻桌面，不用点开菜单栏弹层。登记于 A4 R-2。

本页目录 1. 平台事实（先懂规则再设计） 2. 小组件家族设计（WG-01~06） 3. 交互式控制（桌面直达操作） 4. 数据供给与刷新策略（核心工程问题） 5. 构建与工程落位 6. 风险与边界

1. 平台事实（先懂规则再设计）

事实对设计的影响
桌面小组件自 macOS 14（Sonoma）起支持；macOS 13 上小组件只能放在通知中心侧栏部署目标 macOS 13：小组件功能随系统自适应（13 通知中心 / 14+ 桌面、叠放、交互），不需要分版本开发两套
小组件由独立扩展进程渲染，不能直接读主 App 内存，也不能常驻刷新主 App 把最新快照写入共享快照文件；扩展按时间线（TimelineProvider）取数据渲染
刷新受系统预算控制（WidgetCenter.reloadTimelines 不能无限调）见第 4 节的节流策略：目标"App 运行时 15–60 秒级更新"，不是毫秒级仪表盘
小组件 不能要任何权限（弹不出授权框）只展示主 App 已合法拿到的数据；温度/风扇/电池/性能全满足
交互式按钮（macOS 14+ AppIntent）可在组件内直接执行简单动作风扇模式切换 / 静音 / 全速应急可"桌面直达"，复杂操作深链进弹层

3. 交互式控制（桌面直达操作）

组件内动作（macOS 14+）实现低版本（macOS 13）
风扇模式切换（系统⇄恒速⇄曲线）AppIntent ToggleIntent → 写共享命令文件 + Darwin 通知唤醒主 App 执行（写 SMC 只在主 App/Helper 进程发生，扩展进程绝不碰 SMC）按钮降级为深链：点击打开主 App 弹层风扇页
一键全速应急 / 恢复自动同上，联动 A5·TF-30 应急动作深链
静音切换 / 音量步进AppIntent → 主 App 执行 CoreAudio 操作（复用 E9 动作白名单）深链
查看详情widgetURL 深链 butler://panel/thermal 等直达弹层对应分区同样支持
安全边界：小组件扩展进程只读共享文件、只写命令文件，一切实际系统操作（SMC 写、音量控制）由主 App/特权 Helper 执行——权限与红线治理（A5·第 4 节）不因组件入口而放宽。

4. 数据供给与刷新策略（核心工程问题）

主 App（数据源）
  │ 每次快照更新/温度采样后
  ▼ 原子写 ~/Library/Application Support/StatusButler/widget-snapshot.json
  │   （非沙盒架构红利：主 App 与扩展同用户，共享文件即可，无需 App Group 授权配置）
  ├─ Darwin 通知（com.linzhongyang.statusbutler.snapshot）轻量唤醒
  ▼
WidgetKit 扩展进程
  │ TimelineProvider 读取快照 → 渲染当前 + 预生成未来条目（渐过期预估）
  ▼
桌面 / 通知中心渲染（系统调度）
  • 写入节流：快照文件写入与 WidgetCenter.reloadTimelines 双节流——温度变化 ≥ 2°C、或转速变化 ≥ 300 RPM、或距上次 ≥ 30 秒，三者满足其一才写/刷；杜绝刷新预算被秒级采样烧光。
  • 时间线策略：每次刷新生成"当前值 + 按 5 分钟步进外推的条目"（用最近 10 分钟斜率预估温度走势），预算耗尽时组件显示的仍是合理估计而非冻结旧值；条目带 relevance 提示系统何时最值得刷新。
  • 陈旧标注：快照 mtime 超过 2 分钟（App 退出/睡眠）→ 组件数字降透明度并显示"管家休息中 · HH:MM 数据"；点击深链唤起主 App。
  • 文件一致性：原子写（临时文件 + rename）+ NSFileCoordinator 协调读，扩展读不到时沿用上一次缓存。

5. 构建与工程落位

  • 新增 SPM target StatusButlerWidgets（WidgetKit + SwiftUI），构建产物按 appex 组装进 StatusButler.app/PlugIns/StatusButlerWidgets.appex——沿用本项目"纯 swift build + 脚本组装 .app"路线（与 DDC 模块同等待遇：独立、可摘除，摘除后主 App 不受影响）。
  • 主 App 侧新增 WidgetSnapshotWriter（Monitoring→Store 之后挂一个轻量订阅者）与交互命令监听器，并入 B1 四层架构的 UI/横切层。
  • 签名：appex 与主 bundle 一起 Ad-hoc/Developer ID 签名即可，无额外账号需求（对齐 07 页"0 元路线"）。
  • 测试：快照编码/解码往返、节流决策表（纯函数）、时间线生成器（给定序列 → 断言条目）全部可单测（Swift Testing）；渲染快照测试用固定数据比对。

6. 风险与边界

风险应对
刷新预算紧张，温度显示滞后节流 + 斜率外推 + 陈旧标注三件套；文档与设置页明确"组件是近实时（秒十位级），精确实时看菜单栏图标/弹层"
扩展进程内存上限低组件只读单个 JSON 快照，不维护历史缓冲（历史留在主 App 与 E10）
未来系统收紧共享文件/刷新策略数据通道抽象为协议，可切换 App Group 容器方案；版本矩阵测试钉住行为
macOS 13 无桌面摆放功能页与设置文案按系统版本自适应说明（通知中心可用）
