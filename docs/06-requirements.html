06 / Requirements Baseline

复刻需求基线：做一款"类 Status Trio"的软件

本文把前五页的分析收敛为一份可执行的产品需求基线（PRD）：定位、范围、功能需求（FR-编号）、非功能需求（NFR）、技术决策、里程碑。文末的需求登记表是预留的扩展位——你后续要加的需求，直接登记到那里，再回填对应 FR 编号即可。

本页目录 1. 产品定位与目标用户 2. 版本范围（P0–P3 定义） 3. 功能需求（FR-01 ~ FR-40） 4. 非功能需求（NFR） 5. 技术约束与关键决策 6. 里程碑规划 7. 需求登记表（后续追加区）

1. 产品定位与目标用户

项内容
一句话定位macOS 原生状态聚合工具：把 Wi-Fi、电池、音量（及可选的蓝牙/外设信号）压缩进一个自绘图标，在菜单栏/Dock 常驻，弹层可下钻细节并直接操作。
差异化假设① 一图标多信号，比系统默认省空间；② 弹层即操作中心（连蓝牙、切输出设备、看电池详情）不用进系统设置；③ 外观高度可定制；④（可选）外设电量聚合（AirPods / iPhone / Watch）。
目标用户Mac 重度用户：菜单栏空间敏感者、多设备用户（AirPods/外接显示器/iPhone）、喜欢定制系统状态呈现的高级用户。
非目标用户需要企业管控/MDM 的组织用户；非 macOS 用户。
产品红线不读写 Wi-Fi 密码、不碰钥匙串；不写 SMC/不越权控制充电；隐私权限全部按需最小化申请；遥测默认关闭（若做）。

2. 版本范围

优先级定义对应 Status Trio 能力
P0 · MVP没有它产品不成立三合一图标（菜单栏）、基础弹层、设置中心骨架、事件驱动刷新
P1 · 完整版对标 1.0 的完整体验Dock 双开、下钻页（Wi-Fi/电池详情）、音量操作、蓝牙面板与电量
P2 · 打磨体验与工程化增强充电动画、图标替换/变色、音频输入、VPN/以太网、更新机制、引导
P3 · 差异化重资产可选支线附近 BLE 电量、AirPods 聆听模式、DDC 显示器音量、iDevice 电量

3. 功能需求

状态列约定：基线 = 已纳入本基线；可选 = 实现与否待定（登记表决定）。

3.1 状态图标（FR-01 ~ FR-06）

编号需求优先级状态
FR-01三合一图标：上部电池（百分比/充电/低电色）、中部 Wi-Fi 信号（含关闭/未连接/无网/热点等特殊状态）、下部音量（点阵或弧线两种样式）P0基线
FR-02自绘渲染引擎：矢量几何坐标系 + 系统符号，明暗菜单栏自动适配，符号墨水居中补偿P0基线
FR-03图标外观定制：尺寸、符号缩放（100–180%）、环形描边样式、状态颜色、低电阈值P0基线
FR-04显示位置：仅菜单栏 / 仅 Dock / 双开；Dock 背景跟随系统或固定明暗透明；菜单栏与 Dock 渲染同源P1基线
FR-05充电动画：外环呼吸效果，遵循"减弱动态效果"，显示器睡眠时停止P2基线
FR-06蓝牙音频播放时：中部图标替换为设备专属符号、音量指示变蓝、"网络错误优先"开关P2基线

3.2 弹层面板（FR-07 ~ FR-11）

编号需求优先级状态
FR-07左键弹层：电池/网络/音量概要行（主数值 + 副标题状态）；点击面板外或 Esc 关闭；多屏锚定正确P0基线
FR-08分区编排：每个分区可显隐、可拖动排序P1基线
FR-09下钻导航：Wi-Fi 行 → 附近网络 + 链路详情页；电池行 → 电池详情页；带返回P1基线
FR-10右键菜单：设置、版本、退出（菜单栏与 Dock 通用）P0基线
FR-11弹层资源策略：打开期间才加载重资源（蓝牙扫描/链路读取），关闭即释放；数据 500ms 防抖P1基线

3.3 电池域（FR-12 ~ FR-13）

编号需求优先级状态
FR-12电池概要：百分比、充电中/已接电源、充满时间、低电模式状态、无电池设备表现P0基线
FR-13电池详情页：适配器功率/电压/电流、循环次数、健康度；优化充电暂停状态 → 跳系统电池设置（不越权干预充电）P1基线

3.4 Wi-Fi / 网络域（FR-14 ~ FR-17）

编号需求优先级状态
FR-14当前网络：SSID（按需申请定位授权）、信号分级、频段；特殊状态（热点/临时/共享/有线）识别P0基线
FR-15附近网络列表 + 信号强度；点击网络 → 打开系统 Wi-Fi 设置（不代填密码）P1基线
FR-16链路详情：IP、信道、频段、协商速率、受限网络标记；弹层打开且当前为有线时才读取P1基线
FR-17弹层内开关 Wi-Fi；VPN 状态行与以太网链路行P2基线

3.5 音频域（FR-18 ~ FR-21）

编号需求优先级状态
FR-18音量状态：等级、静音、默认输出设备名称 + 设备分类图标P0基线
FR-19弹层内音量操作：滑杆、滚轮滚动（作用域可选整面板/仅控件、自然方向可选）、静音切换、反馈音P1基线
FR-20输出设备列表：点击切换默认输出；排序/数量可配；音频输入设备控制（默认关）P1基线
FR-21外接显示器 DDC 音量直控（私有 I2C 通道，独立模块可摘除）P3可选

3.6 蓝牙域（FR-22 ~ FR-25）

编号需求优先级状态
FR-22蓝牙面板（默认关，开启时申请蓝牙权限）：配对设备列表 + 连接状态 + 电量；AirPods 左/右/盒三分电量P1基线
FR-23设备操作：点击连接/断开；HID 设备（键鼠/手柄）行内二次确认；幽灵设备隐藏/恢复；设备排序与最大可见数P1基线
FR-24电量多源合并：系统配对报告为主、配件电源报告补缺，事件驱动刷新P1基线
FR-25附近 BLE 设备电量扫描（默认关、允许列表、仅面板可见时扫描）；AirPods 聆听模式切换P3可选

3.7 外设与扩展（FR-26 ~ FR-27）

编号需求优先级状态
FR-26USB 连接的 iPhone/iPad/Apple Watch 电量读取（libimobiledevice Helper 路线）P3可选
FR-27（复刻扩展位）自定义信号槽：允许用户选择中部图标来源（如时钟/日历/自定义符号）——Status Trio 未做，属我们的候选差异点P3可选

3.8 设置 / 系统 / 发布（FR-28 ~ FR-40）

编号需求优先级状态
FR-28设置中心：分区导航 + 即时预览卡片；全部设置持久化（UserDefaults），含取值范围校验与跨版本迁移P0基线
FR-29首次启动引导："认识你的图标"图文页；可从设置重开P2基线
FR-30本地化框架：至少 中/英；字符串外置；App 语言可独立于系统语言（目标：12 语言看运营）P1基线
FR-31开机自启动（现代 LoginItem API）+ 单实例锁P1基线
FR-32自动更新：Sparkle 2 + EdDSA 签名 appcast（或初期仅 GitHub Releases 手动）P2基线
FR-33发布流水线：GitHub Actions 全自动出包（DMG + SHA-256），Developer ID 签名 + 公证（有证书时）P2基线
FR-34遥测（可选、默认关、匿名心跳）——初期建议不做，登记表决定P3可选
FR-35无障碍：图标与面板的 Accessibility 标签P2基线
FR-36系统设置深跳：跳 Wi-Fi 面板 / 电池面板等，路由必须落到目标面板自己的 Settings 扩展，并有路由测试P1基线
FR-37（复刻扩展位）菜单栏额外能力：如快捷开关飞行模式类动作面板——Status Trio 刻意未做，候选差异点P3可选
FR-38（复刻扩展位）图标主题/皮肤市场或导入导出配置方案P3可选
FR-39（复刻扩展位）Windows / 跨平台版本——重大范围变更，需专项立项P3可选
FR-40（复刻扩展位）CLI / URL Scheme / Shortcuts 集成，供自动化调用P3可选

4. 非功能需求

编号类别要求
NFR-01能效事件驱动优先；兜底轮询默认 15s（5–60s 可调）；界面不可见时 Wi-Fi/音量降为每 4 tick 一次；显示器睡眠跳过轮询但设自愈上限；定时器带宽容忍
NFR-02性能图标状态不变不重绘（快照相等性 + 渲染缓存 key）；高频刷新合并（coalescer）；弹层打开首帧 < 100ms（数据防抖）
NFR-03隐私红线不读 Wi-Fi 密码/不碰钥匙串；定位与蓝牙权限按需最小化；遥测默认关且字段最小化；权限用途在引导与设置中说明
NFR-04兼容最低 macOS 13（或 14，立项定）；Universal 双架构；Ventura 真机验证后再宣称支持
NFR-05可靠性单实例；崩溃不影响系统状态（只读系统为主）；DDC/私有通道失败静默降级到不可用而非崩溃
NFR-06可测试监控器协议化可注入；映射层纯函数；核心路径单元测试覆盖；图标几何/像素级回归（从 M2 起引入）
NFR-07可维护组合根装配；AGENTS.md 工程规则随仓库；设计文档快照制（不追溯修改）；菜单栏/Dock 对等原则
NFR-08安全更新源签名（EdDSA）；发布物 SHA-256；不引入未审计的网络回调（App 内请求仅限更新与可选遥测，且仅 https）

5. 技术约束与关键决策（立项即定）

决策点推荐理由 / 备注
语言/并发Swift 6 严格并发，核心 Store @MainActor与蓝本一致，状态一致性收益大；注意 deinit 隔离限制
UI 结构AppKit 壳（NSStatusItem/NSPopover）+ SwiftUI 内容 + CoreGraphics 自绘图标菜单栏工具事实标准
包管理SPM（可 选 Xcode 工程托管）依赖极少，SPM 足够
架构四层：Monitoring（协议化）→ Store（单快照）→ Presentation（纯映射）→ UI直接复刻蓝本分层（见 04 页）
运行时依赖Sparkle 2（P2 引入）唯一必要三方依赖；其余自研
私有 API 政策DDC 独立 target 封装，可整体摘除；不引入其他私有符号控制风险面
iDevice 电量P3 独立里程碑；依赖锁定 manifest + 契约脚本照抄蓝本最重的支线
分发Developer ID 自分发（非 MAS）MAS 沙盒会砍掉 DDC/Helper 等能力

6. 里程碑规划（建议）

M1 · 骨架跑通 P0

组合根 + 单实例 + 菜单栏图标渲染三信号（电池/Wi-Fi/音量基础态）+ 事件驱动与兜底轮询 + 基础弹层（概要行 + 右键菜单）+ 设置骨架（外观 4 项）+ 单元测试基建。
验收：菜单栏图标随系统状态实时变化；空闲 CPU 占用可忽略。

M2 · 完整弹层 P1

分区编排与排序 + Wi-Fi 附近网络/链路详情 + 电池详情页 + 音量操作（滑杆/滚动/设备切换）+ 设置中心完整化 + 中英本地化 + 登录启动。
验收：不看系统设置即可完成 FR-09/13/15/16/19/20 全部操作。

M3 · 蓝牙域 P1

蓝牙面板（授权流程）+ 配对设备管理 + 多源电量合并 + AirPods 分体电量 + 菜单栏/Dock 双开与 Dock 渲染。
验收：弹层内完成连接/断开；Dock 图标与菜单栏像素一致。

M4 · 打磨与发布 P2

充电动画 + 蓝牙图标替换/变色 + VPN/以太网行 + 首次引导 + 无障碍 + Sparkle 更新 + GitHub Actions 出包（DMG+签名公证）+ 像素回归测试。
验收：对外可发布的 1.0。

M5 · 差异化支线 P3

按登记表决策：DDC 显示器音量 / 附近 BLE 电量 / 聆听模式 / iDevice 电量 / 自定义信号槽等。
验收：逐项独立验收，任一支线可砍。
