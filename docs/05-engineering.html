AGENTS.md：AI 协作规则

作者把给 AI 编码智能体的约束固化在仓库根的 AGENTS.md，配合 .agents/skills/ 下 25 个 vendored 技能与 skills-lock.json 锁定文件。核心规则摘要：

规则域内容要点
CI 工具链匹配（最高优先级）本地编译通过不算数，macos-26 / Xcode 26.6 / Swift 6.3.3 通过才算；SDK 必须 ≥ 26（旧 SDK 会静默产出旧外观，构建脚本与 verify-platform-version.sh 双保险）
提交前验证swift test + swift build -c release；触碰 actor 隔离 / @MainActor / deinit / SwiftUI 绑定 / 泛型 / Bundle.module 的改动，额外跑一次不发布的 release workflow 预检
Swift 6 兼容军规禁用 isolated deinit 实验特性；不把 actor 隔离方法直接当函数值传；禁 weak let；Bundle.module 资源名/大小写不可假设（要同时尝试规范与小写 lproj 名）；编译器崩溃（IRGenRequest / SmallVector / signal 6）必须收敛代码模式而非绕过
失败登记每次 CI 失败必须记入 docs/swift-ci-compatibility.md：run ID、失败阶段、根因、修复、验证结果
图标对等菜单栏与 Dock 图标必须同一改动内同步（设置派生 → 订阅 → 缓存 key → 渲染 → 测试五处）；菜单栏专属设置需文档+测试声明豁免
Issue #30 看护触碰图标渲染/几何/映射的改动必须跑 Issue30WiFiAlignmentTests；两条居中回归不许删除或放宽
系统设置路由设置控件必须落到对应面板自己的 Settings 扩展（Wi-Fi 齿轮 → Wi-Fi 面板而非 Network 面板）；首个路由决定目的地；验证方法是看加载的扩展（pgrep ExtensionKit）而非 open 的退出码；发布后发现的问题要先用 strings 读二进制里的路由顺序再下结论
发布规则版本/构建号必须显式且递增；Release 正文 = 英文在上中文在下（en.md + zh-Hans.md 组合）；Sparkle appcast 每语言独立 title/description 且 xml:lang 显式、en 必须第一；Developer ID 签名版不许附 quarantine 指引，仅 Ad-hoc 回退时附；发布永远走 workflow，不手工
变更流小改动直进 main；大改动/跨子系统走 PR；PR 本身不触发 CI（release workflow 只在 tag/手动时跑），所以验证规则与路径无关一律执行
💡 这份 AGENTS.md 对我们的复刻项目几乎可以"抄了就用"：把工具链版本、对等原则、发布纪律替换成自己的即可。把 AI 协作规则放进仓库而不是聊天记录，是保证多次会话之间工程质量一致的关键。

质量守门机制

  • 测试 / 源码 ≈ 1.4 : 1：231 个测试文件覆盖从纯逻辑到像素指纹；
  • 守卫测试（ForbiddenPatternGuardTests + shell 扫描）：把"代码里不许出现 X"变成 CI 断言——例如禁止危险的私有调用模式扩散；
  • 回归看护：真实事故（Issue #30 居中、#40 SDK 外观）转化为永不删除的回归测试 + AGENTS.md 条款——问题只发生一次；
  • NOTICE + LICENSE 合规：Apache-2.0 主协议 + 第三方 LGPL 库清单随仓库分发；
  • 隐私文档：docs/privacy-telemetry.md 公开遥测全字段、同意机制与保留策略，并有 telemetry-verification.md 验证记录。
