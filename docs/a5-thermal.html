A5 / Thermal & Fan（E11 深度设计）

温度与风扇：对标 TG Pro 的温控模块

状态管家的第 11 号扩展（E11）：全传感器温度监测 + 风扇转速监测与控制 + 温度警报，对标 TG Pro（Temperature Gauge Pro）与 Macs Fan Control。本页是资料调研 + 详细功能设计 + 技术方案 + 安全护栏，登记于 A4 R-1。

本页目录 1. 竞品与开源资料调研 2. 功能设计（TF-01 ~ TF-30） 3. 技术方案：SMC 访问原理 4. 安全护栏（本模块的生命线） 5. 界面设计 6. 风险与边界 7. 红线修订说明

1. 竞品与开源资料调研

产品/项目能力对本项目的参考价值
TG Pro（商业，~$15）温度传感器显示数量最多（CPU/GPU/LCD/电源等全覆盖）、手动风扇转速、按传感器自动提速、温度/风扇通知、菜单栏多温度显示、日志导出；支持 Apple Silicon（M1 iMac、M1 Max 等专属传感器映射）对标基准：功能全集与产品形态
Macs Fan Control（商业，CrystalIDEA）自定义温度→转速曲线（每风扇独立）、恒定 RPM、系统自动三模式；Apple Silicon 上首次控制风扇时要求安装特权 Helper（输管理员密码）曲线编辑器的交互范式；特权 Helper 的权限模型
iStat Menus（商业，Bjango）传感器只读监测的标杆，曲线图与菜单栏显示传感器分组展示与历史曲线 UI
stats（开源）macOS 菜单栏监测器，Sensors 模块读全部温度 + 风扇 RPM，只读不控制；维护了按机型的传感器键位目录（Intel + Apple Silicon）★ 最重要的技术参考：机型→键位映射表、读取实现（Swift）
smcFanControl（开源，Intel 时代）经典风扇控制：抬高最小转速（只升不降），写 SMC 键 FS! （强制模式）与 F0Md（目标转速）；Intel 上用户态直接可写★ 风扇写入键位与"只升不降"安全哲学
Core-Monitor、beltex/smctemp（开源）Apple Silicon 监测（温度/功耗/风扇）；smctemp 是读 Apple Silicon CPU 温度的最小 CLI 实现Apple Silicon 读取路径验证
调研结论：① 读温度/转速——用户态直接读 SMC，无权限门槛，开源实现充分；② 写风扇转速——Intel 上用户态可直接写，Apple Silicon 上需要特权 Helper（Macs Fan Control / TG Pro 均如此）；③ 传感器键位因机型而异，必须维护"机型目录 + 探测兜底"，stats 的映射表可直接借鉴。

2. 功能设计（TF-01 ~ TF-30）

TF-A 温度监测

TF-01 传感器全景监测

  • 读取并分组展示：CPU（封装/各性能核/各能效核）、GPU（核心/显存附近）、电池/电源、存储（SSD）、主板/外壳（掌托、进风口）、其他外设传感器——凡本机 SMC 暴露的温度键全部收录（对标 TG Pro"传感器最多"）。
  • 机型目录：按设备型号（如 MacBookPro18,3 / Mac14,2）映射该机型的键位清单与中文名（目录数据借鉴 stats 的映射 + 自测补充）；目录没有的机型走通用探测（按已知键名模式扫描），探测结果允许用户手动隐藏/命名。
  • 异常值防御：传感器故障读数（如 -127°C）标记"不可用"而非显示。

TF-02 图标与槽位集成（联动 E1）

  • 温度成为 E1 信号槽的内置源：CPU 温度 / GPU 温度 / 最高温 三种选择，图标下部显示温度数字 + 热度分级点（绿/黄/红）。
  • 温度超阈值时整个图标温度区变红（可选），与电池低电红色同层级提示。
  • 菜单栏 20pt 图标默认只显示一个温度；Dock 大图标可同屏两路温度。

TF-03 弹层温控面板（联动 S3 分区）

  • 弹层新增"温度与风扇"分区：顶部 当前最高温 + 来源传感器名大字卡；下面按 CPU/GPU/存储/电池/其他分组列出传感器（名称 + °C + 迷你走势条）。
  • 点击任一传感器 → 详情页：60 分钟曲线（联动 E10 历史缓冲）、峰值/均值。
  • 传感器行可收藏置顶（收藏的进图标槽位候选）。

TF-B 风扇监测

TF-10 风扇实时状态

  • 枚举风扇（键 FNum 计数，F0ID/F1ID… 名称）：每风扇显示当前 RPM / 厂商最小 RPM / 最大 RPM，左右/多个风扇并排卡片。
  • 转速迷你走势 + 当前模式徽标（系统自动 / 手动恒速 / 曲线）。
  • 风扇 RPM 也可作为 E1 槽位源；无风扇机型（MacBook Air）自动降级为纯温度模式，风扇区隐藏。

TF-C 风扇控制（核心）

TF-20 三种控制模式 需特权 Helper（Apple Silicon）

  • 系统自动（默认）：不写入，仅监测——安装 App 后零风险起步。
  • 手动恒速：滑杆把风扇设为固定 RPM（钳制在厂商 min–max 区间内；遵循 smcFanControl 的"只升不降"哲学可选开启：仅允许把转速设在系统策略之上，防止压制散热）。
  • 自定义曲线：温度→转速多段折线（对标 Macs Fan Control），每风扇独立一条；控温源可选任一传感器（默认 CPU 封装温度）。

TF-21 曲线编辑器

  • 横轴温度（30–110°C）纵轴转速（min–max RPM），可拖动控制点、双击加点、右键删点；实时预览当前工作点（当前温度↔当前转速的动画点）。
  • 滞回带（hysteresis）：升降温各用一条曲线（默认相差 3°C），防温度在阈值附近来回抖动导致转速锯齿。
  • 内置预设：安静 / 平衡 / 性能 / 全速；用户曲线可保存命名、随主题系统（E7）导出分享。

TF-22 控制引擎纪律

  • 曲线引擎为纯函数（温度序列 + 曲线 + 滞回状态 → 目标 RPM），可完整单元测试；写 SMC 的间隔节流（默认 ≥ 2s，或目标变化 > 200 RPM 才写）。
  • 退出/崩溃恢复：接管时持久化"已接管"标记；正常退出、注销、关机时写回系统自动模式；异常退出后，下次启动检测到标记即先写回系统模式再询问是否恢复接管（绝不带着用户的风扇设置悄悄跑）。
  • 睡眠/唤醒：睡眠时放弃接管，唤醒后重应用；外接电源↔电池切换可配置不同曲线（电池模式转速上限更低）。

TF-D 警报与日志

TF-30 温度警报

  • 按传感器设阈值（默认 CPU 封装 90°C / 电池 40°C）：达到时发系统通知，可选"自动临时全速"应急动作；恢复正常发解除通知。
  • 风扇转速异常警报（转速为 0 但应为旋转中）——可能预示硬件故障，高级用户刚需。
  • 所有警报联动 E10 事件日志，温度历史可导出 CSV（对标 TG Pro 日志导出）。

3. 技术方案：SMC 访问原理

用户态 App ──IOKit──▶ AppleSMC 服务（系统自带内核扩展暴露的 user client）
                        │  IOConnectCallStructMethod：
                        │  SMCReadKey / SMCWriteKey（4 字符键 + 类型化值）
                        ▼
              SMC（系统管理控制器：温度传感器 / 风扇 / 电源）

键位清单（核心）

键含义读/写权限
FNum风扇数量读用户态
F{n}Ac风扇 n 实际转速（RPM，fpe2 类型）读用户态
F{n}Mn / F{n}Mx风扇 n 厂商最小/最大转速读用户态
F{n}ID风扇 n 名称读用户态
TC0P / TC0D…CPU 近端/核心温度；GPU：TG0P 等；电池：TB1T…；掌托：Ts0S…（随机型大量变化，走机型目录）读用户态
FS! 风扇强制模式（01=系统自动，02=强制手动）写Intel 用户态可写；Apple Silicon 需特权 Helper
F{n}Md风扇 n 目标转速（写入值）写同上

权限模型与 Helper 设计

  • 读路径（TF-01/02/03/10）无特权：直接 IOKit 连接 AppleSMC 读取，与 stats 相同——温度监测功能对全部用户默认可用。
  • 写路径（TF-20+）需要特权：Apple Silicon 上用户态无法写风扇键，需要特权 Helper。采用苹果官方 SMAppService 机制安装 LaunchDaemon（仅暴露一个本地 XPC 接口：写入键白名单校验后的风扇命令），首次启用控制时向用户解释并请求管理员授权；卸载随 App 一键完成。这是 Macs Fan Control / TG Pro 的同款路线，也是唯一不动系统完整性的做法。
  • Helper 拒绝执行白名单（FS! 、F0Md/F1Md…）之外的任何 SMC 写入——充电/电源域键一概不碰（红线，见第 7 节）。

4. 安全护栏（本模块的生命线）

风扇是散热安全的最后一道闸，本模块按"最坏情况也不伤机器"设计：
  1. 写入域白名单：代码层守卫 + 独立模块封装 + 守卫测试扫描（延续 DDC 的治理方式），任何风扇域之外的 SMC 写入直接编译期/测试期拦截。
  2. 边界钳制：所有写入 RPM 钳制在厂商 min–max；默认开启"只升不降"（用户可关闭但需二次确认）。
  3. 异常自愈：退出/崩溃/注销恢复系统自动模式（持久标记 + 启动自愈，见 TF-22）；温度超过 105°C 应急全速并通知。
  4. 节流与去抖：写入间隔 ≥ 2s 或变化显著才写；滞回带防锯齿。
  5. 透明可卸：弹层常显当前模式徽标；设置内一键"恢复系统控制并卸载 Helper"；模块整体可摘除（编译开关），摘除后其余功能不受影响。

5. 界面设计

图标（20pt 菜单栏 / Dock）
  • 槽位源显示：78° 数字 + 3 档热度点（<70 绿 / 70–90 黄 / >90 红）
  • 超阈值：温度数字整体变红闪烁一次
  • Dock 图标：可同时显示 CPU/GPU 两路温度
弹层分区"温度与风扇"
  • 顶卡：最高温大字 + 来源 + 迷你风扇转速条
  • 传感器分组列表（可收藏/隐藏）
  • 风扇卡片：RPM + 模式徽标 + 快捷"系统/恒速/曲线"切换
  • 下钻：曲线编辑器 / 传感器详情曲线 / 阈值设置

6. 风险与边界

风险应对
传感器键位无官方文档，机型差异大、系统更新可能增删机型目录（借鉴 stats）+ 通用探测 + 用户可编辑；键读取失败静默降级
Apple Silicon 写风扇依赖非公开行为，未来 macOS 可能收紧写失败自动回退"系统自动"并提示；版本白名单验证后再放开（同 E3 策略）
特权 Helper 是本项目唯一提权点SMAppService 官方机制、XPC 白名单、一键卸载、独立仓库目录与审计
无风扇机型 / 台式多风扇机型按 FNum 自适应：0 风扇纯温度模式；多风扇逐个卡片与曲线

7. 红线修订说明（A2·S12 红线二）

原红线二"不写 SMC、不附带特权进程"针对的是充电/电源越权（Status Trio 的边界）。E11 经产品决策（A4·R-1）引入风扇控制后，修订为：

修订后红线二：禁止任何充电/电源域的 SMC 写入与特权操作；风扇域 SMC 写入（FS! 、F{n}Md）为本项目唯一例外，必须满足：独立模块 + 键白名单 + SMAppService 官方 Helper + 退出自愈 + 一键卸载。温度/转速读取不受限制。
