项目概览：Status Trio 是什么

三个系统信号（Wi-Fi、电池、音量），一个原生 macOS 状态图标——显示在菜单栏、Dock，或两处同时显示。

本页目录 一句话定位与产品灵感 项目基本信息 代码规模与工程画像 核心亮点速览 产品哲学与刻意的"不做" 对我们复刻项目的价值判断

一句话定位与产品灵感

Status Trio 是一款原生 macOS 状态聚合应用：把 macOS 系统中原本分散在控制中心 / 菜单栏 / 系统设置里的 Wi-Fi 状态、电池状态、音量状态 三个信号，压缩进一个 20pt 的自定义绘制图标中；点击图标弹出的面板（Popover）又能下钻到比图标更深的细节：Wi-Fi 附近网络与链路详情、蓝牙配对设备列表、电池详情页、正在播放的音频设备等。

产品灵感来自 iPhone Duo（灵动岛式组合状态栏）把 Wi-Fi / 电池 / 蜂窝合并成一个状态图标的交互，作者将其适配到 Mac 上，用"音量"替换了"蜂窝数据"。

💡 官方网站 statustrio.lingai.net 提供了一个浏览器端的图标状态模拟器，可以在不安装 App 的情况下体验所有图标状态——这也说明该项目的图标渲染核心是数据驱动、与平台无关的几何描述（仓库里的 status-menubar-demo.html 是它的雏形）。

几个值得注意的画像特征：

  • 测试代码比业务代码还多（约 1.4 : 1），且包含像素级回归：充电动画渲染有指纹（fingerprint）测试，Wi-Fi 图标居中有"墨水中心对齐"回归测试（Issue #30），本地化有 12 语言键一致性（parity）测试。
  • 文档密度极高：docs/ 下每个功能都有一份"调查报告 / 设计规格 / 行为矩阵"，docs/superpowers/specs/ 保存了 31 份按日期编号的设计文档，相当于完整的产品决策史。
  • 仓库根有 AGENTS.md（约 100 行的 AI 协作规则）与 .agents/skills/（25 个 vendored 技能），说明作者大量借助 AI 编码智能体开发，并把工程约定固化进仓库。
  • 存在 analytics/ 目录（每日 GitHub 指标快照）与 appcast.xml（18 万行的 Sparkle 更新源文件），发布链路完全自动化。

核心亮点速览

  • 一图标三信号：电池（顶部）+ Wi-Fi 或蓝牙音频设备图标（中部）+ 音量点/弧（底部）共享一个图标；蓝牙播放时音量指示可变蓝。
  • 菜单栏、Dock 或双开：Dock 图标可跟随系统图标风格，或固定深色/浅色/透明背景；通过激活策略（LSUIElement ↔ Regular App）动态切换。
  • 下钻式弹层面板：Wi-Fi 附近网络 + 链路详情（IP、信道、频段、速率）、蓝牙配对设备就地连接/断开、电池详情（适配器功率、电压、电流、循环次数、低电量模式）。
  • 蓝牙设备电量生态：AirPods 左/右耳/充电盒分体电量、附近 BLE 设备电量扫描（CoreBluetooth）、甚至通过静态编译的 libimobiledevice 读取 USB 连接的 iPhone / iPad / Apple Watch 电量。
  • 音频深度集成：输出/输入设备控制、自然滚动方向调节音量、弹层内滚轮调音量、外接显示器通过 DDC/CI 私有 I2C API 直接控制音量、AirPods 通透/降噪模式切换。
  • 高度可定制：图标大小、符号缩放（100%–180%）、环形描边样式、状态颜色、弹层分区显示与否及排序、刷新间隔（5–60s）、充电呼吸动画开关。
  • 能效优先：事件驱动更新 + 慢速轮询兜底；界面不可见时降低轮询步长；显示器睡眠时跳过轮询并带自愈上限；渲染结果多级缓存。

产品哲学与刻意的"不做"

项目在 docs/known-limitations.md 中明确了两条"刻意边界"，这对我们复刻项目的需求取舍最有参考价值：

边界一：切换 Wi-Fi 网络必须跳转系统设置。macOS 没有公开 API 可以"用已保存密码连接网络"，任何替代路径最终都会让 App 持有 Wi-Fi 密码。Status Trio 选择在弹层中列出附近网络，点击后打开系统设置的 Wi-Fi 面板，从不读取、从不存储 Wi-Fi 密码，从不申请钥匙串权限。
边界二："立即充满"留在 macOS 手里。当优化充电或充电上限暂停充电时，弹层只报告暂停状态并链接到电池设置面板；没有公开 API 允许 App 越过上限继续充电，项目拒绝写 SMC、拒绝附带特权 Helper去做这件事。

同样的克制还体现在：位置权限仅在用户选择显示 Wi-Fi 名称时才申请（macOS 用定位权限保护 SSID）；蓝牙权限仅在显示蓝牙面板时申请；遥测默认关闭、内容最小化（随机安装 ID + 版本 + 语言 + 图标位置，无任何硬件标识）。

对我们复刻项目的价值判断

把 Status Trio 作为蓝本做"同类软件"，它的可借鉴性与风险点同样突出：

✅ 高价值可借鉴⚠️ 需要评估的风险 / 成本
• 分层架构清晰：Monitoring → Store → Presentation → UI，协议化监控器便于注入测试
• 事件驱动 + 兜底轮询的能效模型，细节（步长、睡眠跳过、自愈）可直接抄
• 图标渲染管线（场景状态 → 几何 → 渲染器 → 缓存 → 合并刷新）
• 60 项设置的数据模型与设置中心分区方式
• 发布工程：Sparkle + 多语言 appcast + GitHub Actions 全自动出包 		• 构建门槛：必须 Xcode 26 / macOS 26 SDK，CI 用 macos-26 runner + Swift 6.3.3
• DDC 音量、libimobiledevice 电量属于私有 API / 第三方 C 库，稳定性与审核风险自担
• 图标像素级回归测试成本高（但对长期演进价值大）
• 与 macOS 系统行为深度耦合（弹层玻璃效果、SF Symbols 墨水居中等），每次系统更新都可能返工
• 测试/文档投入约占总代码量 60%+，复刻预算需预留
